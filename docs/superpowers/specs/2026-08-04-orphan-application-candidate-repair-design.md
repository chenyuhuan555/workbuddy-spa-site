# 推进记录孤立人才关联修复设计

## 目标

修复 `applications.candidateId` 无法在当前有效 `candidates.id` 中找到而导致推进中心显示“人才已删除”的问题，同时完整保留推进阶段、负责人、时间线、备注和岗位关系。修复过程必须可审计、可预览、可回滚，并阻止同类无效关联再次进入云端权威读路径。

## 已确认现象

- 推进记录、公司和岗位仍存在，只有人才名称查找失败。
- 推进中心的“人才已删除”是查找失败的兜底文案，不是删除审计结论。
- “当前推进中”按推进记录里的不同 `candidateId` 计数，没有验证对应人才是否存在。
- `applications.candidate_id` 当前没有数据库外键，Phase 2 候选人校验与 Phase 3 业务实体校验也没有跨表检查。

## 方案比较

### 方案 A：直接按姓名批量改 ID

实现最快，但同名人才、脱敏姓名和资料不完整时可能串错推进历史，不采用。

### 方案 B：删除孤立推进并重新创建

可以消除页面异常，但会丢失阶段、负责人、时间线、备注和更新时间，不采用。

### 方案 C：审计、确定性映射、分阶段修复

先生成只读报告，只对具备唯一强证据的记录生成更新计划；应用更新前保存备份，更新后重新执行完整性校验。无法唯一匹配的记录保留并进入人工确认清单。采用此方案。

## 修复流程

### 1. 只读审计

读取候选人和推进记录，输出：

- 候选人总数、推进记录总数。
- 正常关联数、孤立推进数、孤立人才 ID 数。
- 每个孤立人才 ID 关联的推进数量、公司、岗位、负责人和时间范围。
- 是否存在可用于恢复身份的旧候选人行、墓碑行或兼容快照记录。

审计阶段不得修改任何业务数据。

### 2. 确定性映射

映射按以下优先级执行：

1. 旧候选人 ID 对应记录的 `sourceResumeId` 或简历文件哈希，与唯一有效人才一致。
2. 规范化手机号或邮箱，与唯一有效人才完全一致。
3. 多个强字段组合唯一一致，例如姓名、当前公司和当前职位，同时不存在冲突。

仅姓名相同、只有模糊相似或出现多个候选目标时不得自动修复。一个旧 ID 只能映射到一个新 ID；多个旧 ID 可以在强身份一致时汇聚到同一人才。

### 3. 修复预览与备份

生成修复计划，逐项包含：

- 推进记录 ID、旧 `candidateId`、目标 `candidateId`。
- 匹配依据和置信级别。
- 将保留的阶段、负责人、时间线和备注摘要。

执行前导出候选人、推进记录及相关迁移元数据备份。备份成功是写入的硬门槛。

### 4. 执行更新

只更新修复计划中已唯一确认的 `applications.candidate_id`，不删除或重建推进记录，不修改候选人、岗位、公司和推进业务字段。更新采用幂等方式：重复执行不会产生新的变化。

无法确认的记录保持原样，并在报告中显示“需要人工确认”。

### 5. 修复后验证

- 更新前后人才、推进记录、公司和岗位数量保持不变。
- 阶段、负责人、时间线、备注和创建时间保持不变。
- 已修复记录全部能关联到有效人才。
- 孤立推进数等于未确认清单数量。
- 刷新页面和重新从云端读取后结果一致。

## 防复发改动

### 应用层

- 增加独立的推进关联完整性模块，输入候选人与推进记录，输出正常、孤立和可修复集合。
- Phase 3 云端读取启用及一致性验证必须额外检查所有活跃推进的 `candidateId` 是否存在于有效候选人集合。
- “当前推进中”只统计仍存在的有效人才。
- 页面将兜底文案改为“人才关联失效”，避免把关联错误误报为删除事实。

### 数据库层

历史孤立数据清零后，再评估为 `applications.candidate_id` 增加指向 `candidates.id` 的外键。候选人继续使用软删除，不能级联删除推进历史。外键迁移必须独立执行并可回滚。

## 模块边界

新增纯函数模块负责：

- 扫描孤立关联。
- 规范化强身份字段。
- 生成唯一映射候选和拒绝原因。
- 生成幂等修复计划。
- 验证修复前后业务字段未变化。

模块不直接访问 Vue、Supabase、浏览器存储或页面 DOM。页面或一次性管理动作负责读取数据、展示预览、备份和提交更新。

## 测试

至少覆盖：

- 有效推进不会被误判。
- 缺失人才 ID 被识别为孤立关联。
- 文件哈希、原简历 ID、手机号和邮箱的唯一匹配可生成计划。
- 同名、多目标、冲突身份和弱证据不会自动生成计划。
- 修复只改变 `candidateId`，完整保留其他推进字段。
- 重复执行计划保持幂等。
- 权威读取闸门在存在孤立推进时拒绝启用。
- 推进中人数不再统计不存在的人才。

## 验收标准

- 不删除人才、推进记录或业务历史。
- 自动更新只发生在唯一强证据匹配上。
- 执行前存在可恢复备份和可审阅修复计划。
- 修复后推进中心显示正确人才姓名；无法确认的记录明确列出而不被猜测关联。
- 全量测试、生产构建和线上浏览器验证通过。
