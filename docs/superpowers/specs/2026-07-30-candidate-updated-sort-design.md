# 人才列表按最近更新时间排序设计

## 目标

人才库列表默认按照人才主档的最近更新时间从新到旧排列。新上传简历建立或更新的人才应立即出现在第一页最上方。

## 排序规则

1. 使用 `candidate.updatedAt` 作为首要排序时间。
2. `updatedAt` 缺失时回退到 `candidate.createdAt`。
3. 时间较新的记录排在前面。
4. 时间相同时使用人才 `id` 做稳定排序，避免响应式刷新后顺序随机变化。
5. 无有效时间的数据排在有有效时间的数据之后。

## 数据流

排序发生在人才筛选和分类筛选完成之后、分页之前：

`全部人才 → 条件筛选 → 分类筛选 → 更新时间降序 → 每页 50 条`

因此搜索、分类、人才方向、负责人和状态筛选后的结果都遵守同一排序规则，第一页始终包含当前筛选范围内最近更新的人才。

## 范围边界

- 不修改人才数据结构。
- 不修改分页大小和筛选行为。
- 不把岗位推进记录的更新时间计入人才排序。
- 不修改公司列表和推进列表的排序。
- 继续使用既有上传、编辑和 AI 处理流程维护的 `candidate.updatedAt`。

## 验证

- 增加排序辅助函数测试，覆盖更新时间、创建时间回退、无效时间和相同时间。
- 增加页面静态契约测试，确认排序位于筛选之后、分页之前。
- 运行完整测试和生产构建。
