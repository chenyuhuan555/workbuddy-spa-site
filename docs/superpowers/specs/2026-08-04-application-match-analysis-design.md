# 候选人-岗位 AI 匹配分析设计

## 目标

在候选人与岗位的单条推进记录详情中，增加 AI 匹配分析能力。分析结果必须绑定当前 `application`，同一候选人进入不同岗位时分别保存，不互相覆盖。

## 范围

包含：

- 当前推进记录详情页的“AI 匹配分析”入口。
- 基于当前候选人资料、简历文本、岗位信息和岗位关键词生成结构化分析。
- 将结果保存到当前推进记录的 `aiMatchAnalysis` 字段。
- 展示匹配分数、结论、优势、风险、待核实问题和推进建议。
- AI 不可用、输入不足、网络失败、保存失败和重复点击的明确状态处理。
- 独立动作模块与单元测试。

不包含：

- 批量分析所有候选人。
- 修改候选人基础资料、岗位资料或推进阶段。
- 将分析结果保存到候选人全局记录。
- 引入新的后端表或 SQL 迁移。

## 数据契约

```js
application.aiMatchAnalysis = {
  score: 0,
  conclusion: '',
  strengths: [],
  risks: [],
  verifyQuestions: [],
  recommendation: '',
  generatedAt: '',
  model: ''
}
```

旧的推进记录没有该字段时按空值处理。重新分析成功后替换当前推进记录的分析结果；失败时保留已有结果。

## 用户流程

1. 用户打开某个候选人与岗位的推进详情。
2. 点击“AI 匹配分析”。
3. 页面校验候选人、岗位、岗位职责或关键词、候选人简历文本是否可用。
4. 调用现有 AI 网关，按钮进入处理中状态。
5. 成功后展示并保存结构化结果，显示生成时间。
6. 用户可重复分析，结果只更新当前 `application`。

## AI 输出

AI 必须返回 JSON，字段对应 `score`、`conclusion`、`strengths`、`risks`、`verifyQuestions` 和 `recommendation`。分数限制在 0–100。解析失败时不写入半成品，页面显示“AI 返回格式无法识别”。

提示词需要明确要求从技能、经历、行业、职级/薪资和岗位职责进行判断，并区分事实、推断和待核实信息，避免把简历中不存在的内容当作事实。

## 错误与降级

- 候选人不存在：不发起请求并提示数据已失效。
- 岗位职责和关键词均为空：提示先补充岗位信息。
- 候选人无可用简历文本：提示先完成简历提取。
- AI 或网络失败：提示具体但脱敏的失败原因，保留旧结果。
- 保存失败：显示保存失败，不关闭分析结果区域，不标记为成功。
- 分析进行中再次点击：忽略重复请求。

## 模块边界

新增 `src/ui/application-match-analysis-actions.js`，只负责：

- 输入校验。
- AI 请求参数和结构化结果解析。
- 分数与数组字段归一化。
- 调用注入的保存函数和提示函数。

入口文件只负责组装当前 `application`、候选人和岗位数据，以及将结果写回现有工作区保存链路。模块不直接访问 Vue、Supabase 或全局工作区。

## 测试

至少覆盖：

- 成功生成并保存结构化结果。
- 缺少岗位信息或候选人文本时拒绝调用 AI。
- AI 请求失败时保留旧结果并返回错误状态。
- 非法 JSON 或字段类型错误时拒绝保存。
- 重复触发被阻止。
- 保存失败时不覆盖旧结果。

## 验收标准

- 当前推进记录可以生成并看到匹配度和具体原因。
- 同一候选人关联两个岗位时，两条推进记录的结果独立。
- 刷新后结果仍在当前推进记录中。
- AI 失败不会清空已有匹配分析。
- 模块化测试、全量测试和生产构建全部通过。
