# WorkBuddy 人才库增强版 Excel 工作表设计

## 1. 背景与目标

本轮只改 WorkBuddy 的人才库列表页和候选人概览入口。目标是借鉴《人选情况.xlsx》的信息密度、横向浏览效率和批量比较体验，把人才库改造成一个增强版人才工作表，同时保留系统已有的搜索、筛选、分页、候选人详情、Application 多流程、原始简历和云端同步能力。

优先级固定为：数据正确性 > 操作效率 > UI 美观。

本轮不修改工作台首页、公司库、岗位库、候选人推进页、面试看板、AI 工具箱、数据库结构或现有状态机。

## 2. 已确认的交互方向

采用“高密度主表 + 右侧候选人详情抽屉”。

- 人才库列表始终保留在背景中，顾问查看候选人后仍能保持当前搜索、筛选、分页和横向滚动位置。
- 点击姓名打开右侧抽屉；整行不作为默认详情入口，避免误触并保留行内操作空间。
- 抽屉默认打开“原始简历”，并提供结构化信息、推荐记录、面试进度、跟进记录和 AI 分析六个页签。
- 抽屉右上角保留“完整页面打开”，用于需要大面积阅读或编辑的低频场景。
- 抽屉模式和完整页面模式复用同一份候选人详情内容、数据计算和简历加载逻辑，不维护第二套 Candidate Detail。
- 最右侧操作列只显示“···”，现有查看详情、记录触达、匹配岗位、创建推荐、编辑人才等操作进入菜单。

## 3. 页面结构

### 3.1 顶部操作区

第一行：页面标题、统一搜索框、自定义列、更多功能、新增人才。

搜索覆盖姓名、当前公司、当前岗位、学校/学历、履历摘要、技能、标签、人才方向、Base、`extraFields` 和可用的简历文本。当前独立占据大块版面的“云端全文搜索结果”区域取消，云端与本地命中统一回到人才主表中表达。

第二行：紧凑 Filter Bar。默认不展开大型筛选面板。支持入库时间、触达时间、推荐时间、岗位、Base、归属顾问、当前流程、学历和候选人资产状态组合筛选。

筛选区右侧只显示轻量文字统计：当前结果、本周入库、本周已触达。待跟进只有在现有结构化数据可以可靠计算时才显示。

### 3.2 人才主表

默认列顺序：

1. 姓名
2. 当前公司 / 当前岗位
3. 年龄
4. 履历摘要
5. 当前 Base
6. 期望 Base
7. 当前薪酬
8. 期望薪酬
9. 求职动机
10. 当前流程
11. 归属顾问
12. 最近触达
13. 入库日期
14. 操作

姓名列固定在左侧，表头固定在顶部，操作列可固定在右侧。桌面端优先，字段超出容器宽度时水平滚动，不强行压缩。表格行高控制在约 48px；长文本显示一至两行并截断，完整内容通过 tooltip 或详情抽屉查看。

### 3.3 自定义列

自定义列至少支持姓名、当前公司、当前岗位、年龄、学历、履历摘要、当前 Base、期望 Base、当前薪酬、期望薪酬、求职动机、到岗周期、推荐评语、目前流程、归属顾问、最近触达、入库日期、更新时间和备注。

姓名固定且不可隐藏。其余列偏好保存到 LocalStorage，不新增后端设置表。读取失败或数据损坏时回退到默认列。

## 4. 数据模型与字段映射

### 4.1 数据边界

- Candidate 是全局人才资产，只保存人才基础资料和资产状态。
- Application 是候选人与具体岗位/公司的正式推进记录，流程阶段只从 Application 和现有 WorkBuddyPipeline 读取。
- Position 和 Company 用于补齐 Application 对应的岗位与公司名称。
- ResumeVersion 和原始简历加载服务继续负责原始文件、文本和版本读取。
- 当前实现的归属顾问字段是实体上的 `owner` 字符串，并通过 `src/ui/workbench-owners.js` 统一拆分、收集和筛选。本轮沿用该真实结构，不新增 `consultant`、`belongTo`、`headhunterOwner`、`ownerId` 或 `ownerName` 平行字段。

### 4.2 Excel 与 WorkBuddy 映射

| Excel 字段 | WorkBuddy 来源 | 类型 | 空值处理 |
| --- | --- | --- | --- |
| SN | 不进入人才资产 | 不使用 | 不展示 |
| 日期 | `candidate.createdAt` | 直接读取 | `-` |
| 流程情况 | Application 最新有效阶段 | 组合计算 | `-` |
| 做单顾问 | `candidate.owner`，必要时沿用现有 owner 回退逻辑 | 直接读取 | 未分配 |
| 岗位 | `candidate.currentTitle`；流程岗位从 Position 读取 | 直接/关联 | `-` |
| 姓名 | `candidate.name` | 直接读取 | 未命名候选人 |
| 年龄 | 现有候选人字段或 `candidate.extraFields` | 兼容读取 | `-` |
| 履历 | `candidate.summary` 优先，必要时组合学历、岗位、方向和画像 | 组合计算 | `-` |
| 当前 Base 地 | `candidate.city` | 直接读取 | `-` |
| 期望 Base 地 | 现有候选人字段或 `candidate.extraFields` | 兼容读取 | `-` |
| 薪酬信息 | 现有候选人字段或 `candidate.extraFields` | 兼容读取 | `-` |
| 期望薪酬及依据 | 现有候选人字段或 `candidate.extraFields` | 兼容读取 | `-` |
| 换工作动机/诉求 | 现有候选人字段、画像文本或 `candidate.extraFields` | 兼容读取 | `-` |
| 推荐评语 | `candidate.extraFields` 或关联 Application 的现有推荐内容 | 兼容读取 | `-` |
| 离职/到岗周期 | 现有候选人字段或 `candidate.extraFields` | 兼容读取 | `-` |
| 简历 | ResumeVersion / original resume | 直接关联 | 显示暂无原始简历 |
| 备注 | Candidate 关联 notes 或 `candidate.extraFields` | 关联/兼容 | `-` |
| 目前流程中的企业/同期在看 | Applications + Positions + Companies | 组合计算 | `-` |

年龄、期望 Base、当前/期望薪酬、求职动机、到岗周期和推荐评语当前没有统一的 Candidate 核心字段。现有 Excel 导入会把无法映射的列保存在 `extraFields`，本轮视图适配层读取这些信息，但不会为了提高列表覆盖率新增数据库字段，也不会从简历自由文本中猜测事实。

## 5. 人才表格视图适配层

新增一个独立、无副作用的 UI 视图模块，职责限于：

- 定义默认列和可选列。
- 从 Candidate 直接字段与 `extraFields` 读取兼容值。
- 生成履历摘要和缺省显示值。
- 汇总候选人的有效 Applications。
- 关联 Position、Company 和现有阶段标签。
- 计算入库、触达、推荐日期以及日期筛选边界。
- 执行组合筛选、搜索文本构建和轻量统计。

该模块不写入 Candidate/Application，不负责持久化，不创建状态。纯函数边界便于针对空字段、多流程和日期规则进行单元测试。

## 6. 多 Application 处理

候选人流程只使用现有可见 Application。岗位匹配建议不属于正式流程，不进入当前流程列。

有效流程默认排除已删除、归档和 `closed` 的记录。其余 Application 以最近业务时间倒序排列，业务时间依次取最近 pipeline event、`stageEnteredAt`、`updatedAt`、`createdAt` 中首个有效值。

主表显示第一条的“公司 · 阶段”，存在更多有效流程时显示 `+N`。点击流程或 `+N` 查看全部有效推进，并继续使用现有 Application 详情入口。

该逻辑不会把多个流程合并成 Candidate 的单一面试状态，也不会新增 `candidateFlowStatus`、`candidateInterviewStatus` 或 `talentStatus`。

## 7. 日期筛选口径

### 7.1 入库时间

使用 `candidate.createdAt`。字段无效时不命中日期筛选，不以更新时间代替入库时间。

### 7.2 触达时间

使用候选人关联 Application 中最近一次结构化触达/沟通事件时间。优先取现有 pipelineEvents 中可识别的触达事件以及已有结构化 communication/activity 时间。不从 `communicationLog` 自由文本中的日期字符串推断时间。

### 7.3 推荐时间

使用 Application 首次进入 `recommended` 阶段的 pipeline event 时间。若没有对应结构化事件，不从当前较晚阶段或自由文本倒推推荐日期。

### 7.4 区间规则

今日、本周、本月基于用户本地时区计算闭区间起点和下一周期开区间终点。自定义日期使用起止日期，结束日期包含整日。无效日期不报错、不命中筛选并显示 `-`。

日期维度可以和岗位、Base、归属顾问、流程、学历及人才状态组合使用。

## 8. 候选人详情抽屉

候选人详情现有内容只保留一份，通过显示模式在右侧抽屉与完整页面之间切换。打开列表抽屉时保持人才库主表挂载，关闭抽屉恢复到原滚动位置。

抽屉页签映射现有能力：

- 原始简历：复用原始文件、ResumeVersion 和文本加载逻辑，默认页签。
- 结构化信息：复用现有候选人概览和核心信息编辑能力。
- 推荐记录：展示候选人的 Applications 与推荐信息。
- 面试进度：从 Applications 的现有阶段和 pipelineEvents 汇总。
- 跟进记录：复用现有 notes、activity、communication 数据。
- AI 分析：复用现有 candidate AI notes/工具结果。

原始简历不可用时显示现有错误/缺失状态，并保留重新上传或重试同步能力；不因抽屉模式新增另一套文件加载逻辑。

## 9. 错误与空状态

- 任何可选字段为空时统一显示 `-`，列表保持可渲染。
- 缺少当前公司时仍显示当前岗位；两者均缺失时显示“公司 / 岗位待补充”。
- Application 关联的 Company 或 Position 已删除时使用现有缺失提示，不抛出渲染错误。
- LocalStorage 列偏好损坏时自动回退默认列。
- 原始简历加载失败只影响抽屉简历页签，不影响人才列表和其他页签。
- 长文本仅截断展示，不改变整行高度。

## 10. 预计改动范围

- `index.html`：人才库顶部、Filter Bar、主表、抽屉容器、样式与交互接线。
- `src/ui/talent-library-table.js`：人才表格视图适配、搜索、组合筛选、日期、多流程和列偏好纯函数。
- `src/ui/talent-library-table.test.mjs`：适配层单元测试。
- `src/workbench-v2-ui.test.mjs` 或一个聚焦的人才库 UI 测试：模板接线、固定列、抽屉默认页签和长文本约束。

如现有文件边界能更小地完成同一目标，以最小改动为准；不得顺带重构其他模块。

## 11. 验收与验证

自动化测试至少覆盖：

1. 无 Application 时正常显示 `-`。
2. 一个 Application 时显示公司、岗位和阶段。
3. 三个 Application 时显示最近一条和 `+2`。
4. 缺少期望薪酬或当前公司时不报错。
5. 长求职动机、备注和推荐评语不会撑高行。
6. 100+ 人才筛选、排序和分页数据正确。
7. 本周入库、本周触达、推荐时间和自定义区间边界正确。
8. 归属顾问筛选沿用 `workbench-owners` 规则。
9. 列偏好保存、恢复和损坏回退正确。
10. Candidate 状态与 Application 阶段不混用。
11. 搜索覆盖基础字段、`extraFields`、技能、标签、方向、学历和简历文本。
12. 点击姓名打开抽屉，默认进入原始简历。

实现完成后依次运行聚焦测试、完整相关测试、生产构建和 `git diff --check`。浏览器验收需要检查 Vue 正常挂载、控制台无新增错误、人才库表头和姓名列固定、横向滚动、抽屉开关、六个页签、长文本截断、自定义列、组合筛选和多 Application 展示。

## 12. 非目标

- 不新增数据库表或字段。
- 不改变 Candidate/Application/WorkBuddyPipeline 的职责边界。
- 不改公司库、岗位库、候选人推进页、工作台首页、面试看板或 AI 工具箱。
- 不重新设计全站导航或视觉系统。
- 不重写 `index.html` 或删除现有正常业务逻辑。
- 不把 Excel 的 18 列原样铺满默认视图。
