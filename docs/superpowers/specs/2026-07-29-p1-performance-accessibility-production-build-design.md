# P1 性能、可访问性与生产构建设计规格

## 状态

已确认（2026-07-29）

## 背景与现状

WorkBuddy 仍以大型 `index.html` 承载主要 Vue 模板和业务编排。近期工作已经完成云端/本地冲突保护、退出旧 Gist 同步体系，并开始把同步合并与 IndexedDB 简历缓存拆出为独立模块，但以下问题仍未解决：

- 公司、人才、推进主列表直接渲染全部过滤结果，并在模板行内重复执行数组 `find` / `filter`。
- `columns` 和 `workbenchV2` 的深度监听会直接触发整包序列化、IndexedDB 写入、写后校验与云端推送排队。
- 451 个按钮中有 150 个没有显式 `type`；8 个表单中当前有 1 个表单按钮依赖默认提交行为。
- 多个输入控件主要依赖 placeholder 表达字段含义，缺少稳定的可访问名称及错误关联。
- 页面仍从 Tailwind Play CDN 加载浏览器运行时编译器；仓库中的本地 `tailwindcss.min.js` 也是运行时编译器，不是生产 CSS。
- 页面仍使用 Vue 运行时模板编译和多个内联脚本/样式，因此本轮只能建立基础 CSP；彻底移除 `unsafe-eval` 等例外依赖后续完成 P1-1 模块化和模板预编译。

## 已确认的既有事项

### P0-1 多人登录数据覆盖

核心问题已修复：初始化会判断本地和云端时间，双方同时变化时执行记录级合并，版本冲突后会拉取、合并并重试。后续仍需补充旧版 `jobs` 和双方删除记录的冲突覆盖，但不阻塞本规格。

### P1-1 单文件维护边界

尚未完成。Vite 脚手架、同步合并模块、IndexedDB 缓存模块属于阶段性进展；巨型模板、巨型 `setup()` 和运行时模板编译仍在。因此本规格只进行与目标直接相关的轻量模块提取，不宣告 P1-1 结项。

### P1-2 旧 Gist 同步退出

可以结项。仅保留一次性清除旧 Gist 凭据的兼容代码，不再存在 Gist 读写和合并数据流。

## 目标

1. 把公司、人才、推进主列表的单次 DOM 渲染限制在 50 条以内。
2. 将高频关联读取从逐行线性查找改为一次构建、重复读取的索引。
3. 将高频本地持久化改为 500ms 尾随防抖和单通道串行写入，并向用户显示保存状态。
4. 在不一次性改写所有业务入口的前提下，让深度监听只标记脏数据，不直接发起重型保存。
5. 消除表单按钮的隐式类型，确保输入控件具有可访问名称，错误信息可与字段关联。
6. 移除 Tailwind Play CDN 和浏览器运行时 Tailwind，改为可复现的构建期静态 CSS。
7. 生成依赖/许可证清单，并增加适配当前架构的基础 CSP。

## 非目标

- 本轮不实现虚拟列表；分页验证稳定后再根据真实性能数据决定是否引入。
- 本轮不彻底移除 `columns` / `workbenchV2` 的深度监听；先将其降级为兼容性脏标记入口。
- 本轮不把整个 Vue 应用迁移为 SFC，也不完成 P1-1。
- 本轮不改变 Supabase 数据结构、权限模型、账户边界或云端冲突合并规则。
- 本轮不重做视觉设计，不修改与目标无关的页面和业务行为。

## 设计一：50 条分页与关联索引

### 分页模型

公司、人才、推进分别拥有独立页码状态，统一使用 `PAGE_SIZE = 50`。每个列表产生以下派生状态：

- 过滤后的完整结果；
- 当前合法页码；
- 总页数；
- 当前页切片；
- 当前页起止序号。

筛选条件变化时页码重置为 1。删除记录、权限过滤或远端合并导致结果减少时，页码自动收敛到最后一个合法页，不显示空白越界页。

分页控件提供：首页、上一页、当前页/总页数、下一页、末页以及“当前第 X–Y 条，共 N 条”。禁用状态必须使用原生 `disabled`，保证键盘和读屏语义正确。

详情页返回列表时保留原页码；只有筛选条件变化才回到第一页。

### 索引模型

从 `workbenchV2` 集合派生并缓存以下 `Map`：

- `candidateById`
- `positionById`
- `companyById`
- `applicationsByCandidateId`

为列表统计补充最小必要的分组或计数索引，例如按公司、岗位分组的职位/推进数量。索引随源集合变化重新构建一次，模板行内只做 `Map.get()` 或调用 O(1) 查询辅助函数。

不在模板内重新执行整个集合的 `find` / `filter`。本轮至少覆盖公司、人才、推进三个主列表及因本次修改直接触及的详情关联显示；其他旧页面中的线性查询记录为后续清理项，不扩大本轮修改面。

## 设计二：防抖、串行保存和状态反馈

### 保存协调器

新增独立、可单元测试的保存协调器，职责仅包括：

- 接收 `legacy` 和 `workbench` 两类脏标记；
- 使用 500ms 尾随防抖合并连续修改；
- 同一时刻最多执行一个本地保存批次；
- 保存进行中再次变脏时，在当前批次完成后串行执行下一批；
- 后一次旧任务不得覆盖更新的状态显示；
- 提供 `idle`、`saving`、`saved`、`error` 状态及最近错误；
- 支持测试使用的显式 `flush()`，不依赖真实计时等待。

保存函数必须返回可等待的 Promise。`saveWorkbenchV2()` 的 IndexedDB 整包写入、写后数量校验及元数据保存属于一个串行批次。旧版 `localSave()` 中的异步快照任务也必须纳入可等待结果，不能在函数返回后继续无监管地并发执行。

### 监听兼容层

现有深度监听本轮保留，但职责改为：

1. hydration 期间忽略；
2. 标记对应数据域为脏；
3. 请求保存协调器调度。

监听回调不再直接执行序列化、IndexedDB 写入或云端推送。云端推送继续使用已有防抖和冲突保护，在本地快照成功后调度，避免云端发送一个尚未稳定落盘的中间状态。

下一阶段再逐步将业务写入迁移为 `markLegacyDirty()` / `markWorkbenchDirty()` 等显式命令，覆盖全部入口后删除深度监听。

### 保存状态 UI

在工作台固定但不抢占视觉焦点的位置显示：

- `正在保存…`
- `已保存`
- `保存失败，点击重试`

状态区域使用 `role="status"` / `aria-live="polite"`。错误状态保留最近错误，并提供显式重试；成功状态只代表本地持久化成功，不把尚未完成的云端同步误报为成功。

## 设计三：表单标签和按钮类型

### 按钮

- 所有 `<button>` 都必须显式声明 `type`。
- 表单的真实提交动作使用 `type="submit"`。
- 取消、切换、打开详情、分页、删除等动作使用 `type="button"`。
- 不根据按钮文案猜测行为，需结合所在表单及事件处理确认。

静态测试要求：全页不存在无 `type` 的按钮；同时单独检查表单内按钮，防止后续新增隐式提交。

### 输入控件

每个非隐藏的 `input`、`select`、`textarea` 至少满足一种可访问命名方式：

1. 显式 `<label for="control-id">` 与稳定唯一 `id`；
2. 控件被有可见文字的 `<label>` 包裹；
3. 紧凑搜索/筛选场景使用准确的 `aria-label`；
4. 复用页面现有可见文字时使用 `aria-labelledby`。

业务创建、编辑和登录表单优先使用可见 label。工具栏搜索和紧凑筛选允许使用 `aria-label`，但 placeholder 仅作为示例或格式提示，不能作为唯一名称。

现有字段错误或新增错误区域必须具有稳定 `id`，控件通过 `aria-describedby` 关联；无错误时不产生无效引用。必填状态继续使用原生 `required`，必要时补充可见的必填提示。

## 设计四：Tailwind 生产构建、依赖清单与 CSP

### 构建期 Tailwind

使用与现有页面语义兼容的固定 Tailwind 版本和 lockfile。增加：

- Tailwind 配置文件；
- CSS 输入文件；
- 构建期 CSS 生成命令；
- 生产 CSS 输出文件。

扫描范围至少包括 `index.html` 和 `src/**/*.{js,mjs,html}`。对运行期字符串拼接的类名进行审计，只把真实需要且无法静态识别的完整类名加入 safelist，禁止使用覆盖整个颜色或尺寸空间的宽泛正则。

标准构建必须先生成压缩 CSS，再复制部署文件。`index.html` 改为加载本地静态 CSS，并删除 `https://cdn.tailwindcss.com`。确认无引用后删除 `public/lib/tailwindcss.min.js`，构建产物中也不得再出现该运行时编译器。

### 依赖与许可证

提交并维护：

- 锁定版本的 `package-lock.json`；
- 人类可读的依赖清单，区分构建依赖和浏览器内 vendored 依赖；
- 第三方许可证/来源清单。

CI 使用 `npm ci`，并执行 `npm audit`。无法立即消除的告警必须注明是否可达、运行期/开发期属性及后续处理，而不能静默忽略。

### 基础 CSP

GitHub Pages 无法由本仓库自由配置所有响应头，因此本轮以 HTML CSP meta 为基础保护，并明确其局限。策略应至少：

- `default-src 'self'`；
- `object-src 'none'`；
- `base-uri 'self'`；
- `img-src`、`font-src`、`connect-src` 采用最小必要白名单；
- `script-src` 不再允许 Tailwind CDN、jsDelivr 或 unpkg 回退脚本；
- 禁止通过宽泛 `https:` 代替域名白名单。

当前 Vue 运行时模板编译、内联脚本和内联样式意味着 CSP 仍需有限兼容例外。构建与浏览器回归必须证明策略不会阻断登录、Supabase、DeepSeek、RSS、简历解析及图表等现有功能。P1-1 完成模板预编译后，另行收紧到无 `unsafe-eval`、无脚本 `unsafe-inline` 的策略。

## 测试与验收标准

### 自动化测试

1. 分页在 0、1、50、51、数千条记录下切片正确。
2. 过滤或删除导致页码越界时自动收敛。
3. Map 索引能处理缺失关联和已删除对象，不抛异常。
4. 500ms 内连续修改只产生一个保存批次。
5. 保存进行中再次修改会在完成后串行保存最新快照，最大并发数始终为 1。
6. 保存失败进入 error 状态，重试成功后进入 saved。
7. 所有按钮具有明确 `type`。
8. 所有非隐藏表单控件具有可访问名称，`for` / `aria-labelledby` / `aria-describedby` 引用有效。
9. 生产 `dist/index.html` 不包含 Tailwind Play CDN 或运行时 Tailwind。
10. 生产 CSS 存在、非空，关键响应式和动态状态类可在产物中找到。
11. 现有测试全部通过，内联脚本仍可解析。

### 浏览器回归

使用正式构建产物验证：

- 公司、人才、推进列表翻页、筛选、详情进入和返回；
- 50 条边界、空列表、删除最后一页最后一条记录；
- 连续编辑时保存状态变化且界面不明显卡顿；
- 表单通过键盘操作，标签可点击聚焦对应控件；
- 分页按钮的焦点、禁用和读屏语义；
- 320、768、1024、1440 像素宽度下布局无明显回归；
- 控制台无 CSP、Tailwind、Vue 或资源加载错误；
- 必要外部 API 请求未被 CSP 错误阻断。

## 风险与缓解

- **Tailwind 扫描遗漏动态类名：** 迁移前后截图/关键类产物测试，精确 safelist。
- **保存防抖导致关闭页面前最后一次修改未落盘：** 保留同步 localStorage 关键快照路径，并为可等待持久化提供显式 flush；通过浏览器回归验证刷新场景。
- **串行队列状态被旧任务回写：** 使用批次/版本序号，只有最新批次更新最终状态。
- **批量加标签改变布局：** 业务表单使用现有排版样式；紧凑工具栏使用 aria-label，不强行增加可见行高。
- **CSP 阻断合法功能：** 先枚举真实资源边界，再逐项白名单；禁止为了通过测试退化成全局 `https:`。
- **范围再次膨胀：** 虚拟列表、记录级 Supabase 更新、全面 SFC 迁移和彻底删除深度监听均保留为后续独立工作。
