# 面试进度清理与表格列宽设计

## 目标

面试进度的两个入口统一只展示仍关联有效公司和岗位的推进记录，并把候选人详情中的面试进度卡片改为可比较的表格。两处表格复用现有基础版拖拽列宽交互，不改变业务数据或删除记录。

## 行过滤

- Application 必须处于非 archived/deleted 状态。
- `companyId` 必须能在当前公司集合中找到，且公司未软删除（`deletedAt` 为空）。
- `positionId` 必须能在当前岗位集合中找到，且岗位未软删除（`deletedAt` 为空）。
- 过滤只发生在展示行构建阶段，数据库历史记录保持不变。

## 表格展示

- 主面试/推进工作区保留现有列和点击打开详情行为，增加基础列宽拖拽。
- 候选人详情面试进度改为表格，列为：公司、岗位、当前阶段、面试时间、负责人、最近更新、操作。
- 表头提供无障碍隐藏的拖拽手柄；最小宽度由现有列宽工具统一限制。
- 列宽仅保存在当前页面会话中，刷新后恢复默认值，和当前候选人/岗位表格行为一致。

## 验证

- 纯函数测试覆盖已删除公司、已删除岗位、缺失关联三种情况不生成展示行。
- UI 静态测试覆盖两处面试表格和列宽手柄。
- 运行 `npm test` 与 `npm run build`。
