# 候选人核心信息编辑设计

## 目标

让有写入权限的用户在候选人详情页直接编辑“核心信息”卡片中的技术栈、人才方向、沟通人和联系方式，同时保持人才分类现有的直接勾选行为。保存必须复用 Workbench V2 的人才更新和持久化链路；取消不得产生数据变化。

## 范围

本次只编辑以下四类信息：

- 技术栈：`candidate.skills`。
- 人才方向：`candidate.directions`。
- 沟通人：`candidate.owner`。
- 联系方式：`candidate.phone` 和 `candidate.email`。

本次不编辑姓名、当前公司、当前职位、城市、简历、推进记录、备注、动态、人才分类结构或其他候选人字段。人才分类继续使用现有复选标签和即时保存逻辑。

## 交互设计

### 展示状态

核心信息卡片右上角为有写入权限的用户显示“编辑”按钮。只读用户不显示编辑入口。

展示规则：

- 技术栈继续显示为可扫描的文本或标签；无数据时显示“待补充”。
- 人才方向继续显示标签；无数据时显示“待识别”。
- 沟通人无数据时显示“未分配”。
- 联系方式同时显示手机号和邮箱；二者都为空时显示“待补充”。当前只显示手机号或邮箱其中一个的逻辑不再使用。
- 人才分类维持现有勾选交互，不受卡片编辑状态影响。

### 编辑状态

点击“编辑”后整张卡片进入统一编辑状态，右上角显示“保存”和“取消”。“从简历提取”和“AI 识别人才方向”在编辑期间禁用，避免异步结果与尚未保存的草稿互相覆盖。

字段控件：

- 技术栈：标签编辑器。输入后按 Enter、中文逗号或英文逗号添加；每个标签可单独删除。
- 人才方向：同样使用标签编辑器，支持添加和删除。
- 沟通人：文本输入框，并通过 `datalist` 提供当前工作区已有负责人作为建议；仍允许输入新姓名。
- 手机号：独立文本输入框，允许空值。
- 邮箱：独立 `email` 输入框，允许空值。

标签在保存前统一去除首尾空白、空项和重复项，并保持用户输入顺序。

### 保存与取消

进入编辑状态时创建只包含上述字段的草稿副本，不直接修改 `selectedCandidate`。

保存流程：

1. 校验并规范化草稿字段。
2. 调用 `WorkbenchV2.updateTalent()` 更新当前候选人。
3. 等待 `saveWorkbenchV2()` 完成。
4. 保存成功后退出编辑状态、安排既有云端同步并显示成功提示。
5. 保存失败时保留编辑状态和草稿，显示明确错误，允许用户重试。

取消时直接丢弃草稿并退出编辑状态，不调用更新、保存或云端同步。

## 状态边界

页面增加局部编辑状态：

```js
const candidateCoreEdit = reactive({
  active: false,
  saving: false,
  error: '',
  draft: {
    skills: [],
    directions: [],
    owner: '',
    phone: '',
    email: '',
  },
  skillInput: '',
  directionInput: '',
});
```

切换候选人、离开候选人详情或离开概览标签时，未保存草稿必须被丢弃，避免草稿串到另一位候选人。首版不增加离开确认弹窗；用户主动点击“取消”或切换页面即视为放弃未保存修改。

## 权限与安全

- 编辑入口和保存函数都必须检查现有 `canWrite` 权限，不能只依赖按钮隐藏。
- 所有字段按纯文本处理，不接受 HTML。
- 标签和文本在保存前执行 `String(...).trim()`；渲染继续使用 Vue 文本插值，不使用 `v-html`。
- 不把手机号或邮箱写入控制台日志或错误详情。
- 不新增本地存储键，不绕过 `saveWorkbenchV2()`。

## 可访问性

- 所有操作使用原生 `<button type="button">`。
- 输入框使用可见 `<label>` 或明确的 `aria-label`。
- 删除标签按钮包含标签名称，例如“删除技术栈 Java”。
- 保存期间按钮禁用并显示“保存中…”。
- 错误信息使用 `role="alert"`，不能仅以颜色表达。

## 数据保护

一次保存只能更新：

```js
{
  skills,
  directions,
  owner,
  phone,
  email,
}
```

不得把整个候选人草稿回写到数据对象，避免覆盖 AI 画像、简历版本、分类、推进关系、备注或其他并发更新字段。人才分类继续通过 `updateSelectedCandidateCategories()` 独立保存。

## 测试与验收

### 数据行为

- 保存时仅更新五个底层字段，其他候选人字段保持不变。
- 取消不会调用 `updateTalent()` 或 `saveWorkbenchV2()`。
- 标签去空、去重并保持顺序。
- 保存失败保留草稿和编辑状态。
- 无写权限时不能通过直接调用保存函数修改数据。
- 切换候选人或路由后草稿被清空。

### 界面行为

- 有写权限时显示“编辑”，只读账号不显示。
- 编辑状态显示技术栈、人才方向、沟通人、手机号和邮箱输入控件。
- 沟通人可以选择已有负责人，也能输入新值。
- 联系方式展示时可同时看见手机号和邮箱。
- 保存、取消和标签删除按钮全部声明 `type="button"`。
- 保存失败错误对用户可见。

### 回归边界

- 人才分类勾选仍能使用现有独立保存流程。
- “从简历提取”和“AI 识别人才方向”在非编辑状态仍可用。
- 简历、推进记录、备注与动态不受影响。
- 完整自动化测试和生产构建通过。
- 在浏览器中验证编辑、取消、保存失败、权限和移动端布局。

## 完成标准

- 新增行为先有失败测试，再实现最小代码使其通过。
- 代码修改限定在核心信息卡片、局部编辑状态、保存函数和相应测试。
- GitHub Pages 部署成功后，线上实际验证编辑入口、字段展示和持久化；不能只以工作流完成作为上线成功依据。
