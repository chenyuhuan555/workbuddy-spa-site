# 游客演示数据丰富化设计

## 目标

增强游客演示模式的虚构数据，让首页“公司渠道经营”和人才库列表在首次打开时具备完整、可信的展示内容。

## 范围

- 保留现有 8 位虚构演示人才，并补齐人才库所有现有字段。
- 新增 4 位虚构演示人才，总数为 12 位。
- 补充与新增人才对应的公司、岗位、应用流程、流程事件和渠道来源，使首页渠道经营统计有完整样本。
- 仅修改游客演示数据种子及其测试，不修改真实账号数据、字段定义、筛选逻辑、页面交互或数据库结构。

## 数据约束

- 所有新增记录使用 `demo_` 前缀 ID，并保留 `demo: true` 标记。
- 使用虚构姓名、公司、岗位、联系方式和日期；不使用真实个人信息。
- 每位人才填写姓名、公司/岗位、年龄、学历、履历摘要、当前/期望 Base、当前/期望薪酬、求职动机、流程、归属顾问、最近触达、入库日期和更新时间。
- 新增应用覆盖发现、已触达、筛选、推荐、客户接受、面试和 Offer 等流程状态。

## 验证

- 游客演示数据测试验证总人才数、字段完整度、公司/岗位/应用关联和 demo 隔离标记。
- 运行完整测试与生产构建，确认真实数据边界和现有 UI 行为不受影响。
