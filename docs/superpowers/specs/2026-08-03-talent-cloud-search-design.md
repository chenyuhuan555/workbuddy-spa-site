# 人才库云端全文搜索设计

## 目标

在“人才库”页面增加云端全文搜索入口，调用已存在的 `search_resumes` RPC，搜索姓名、公司、技能、原始简历文本和电子简历文本。现有本地筛选、分页和候选人读取路径保持不变；云端搜索失败时回退到本地筛选，并向用户显示可理解的状态。

## 范围

- 只接入人才库，不修改顶部全局搜索、公司看板或推进中心。
- 只读搜索，不创建、修改或删除候选人及简历版本。
- 云端结果按候选人/简历版本分页展示，点击结果仍进入现有候选人详情页。
- 保留当前候选人列表的本地过滤和最近更新时间排序。
- 不切换候选人云端权威读取路径，也不依赖简历版本云端迁移完成状态。

## 用户流程

1. 用户在人才库搜索框输入关键词。
2. 用户点击“云端全文搜索”。
3. 页面显示加载状态，调用 `resume-search-repo` 的分页搜索接口。
4. 成功时显示匹配候选人、匹配版本、文件名和摘要；支持上一页/下一页。
5. 点击结果打开现有候选人详情，并定位到对应简历版本（若版本仍存在本地）。
6. 云端不可用、未登录、RPC 未部署或请求失败时，保留原输入并显示原因，同时展示本地搜索结果作为回退。
7. 清空关键词或点击“返回人才列表”后恢复现有本地分页列表。

## 数据流与边界

- UI 状态新增独立的 `talentCloudSearch`：`query`、`running`、`page`、`pageSize`、`total`、`items`、`error`、`fallback`。
- 查询通过 `window.WorkBuddyResumeSearchRepo`，不在模板或组件中直接调用 Supabase。
- RPC 参数使用现有 Repository 契约：`search_query`、`result_limit`、`result_offset`。
- 云端结果只保存于内存，不写入 `workbenchV2`，避免搜索结果覆盖本地候选人快照。
- 结果映射使用 `candidateId` 和 `resumeVersionId`；候选人不存在于当前快照时，显示“云端结果，详情暂不可用”，不创建占位人才。

## 错误与回退

- `AUTH_REQUIRED`：提示“请先登录后使用云端搜索”，继续提供本地搜索。
- `RPC_NOT_DEPLOYED` / `BACKEND_REQUEST_FAILED`：提示具体安全错误码，不暴露底层响应内容，继续提供本地搜索。
- 空关键词不发起云端请求，只显示本地列表。
- 新查询取消或覆盖旧查询，旧响应不得覆盖新结果。
- 搜索失败不清空上一次成功的云端结果，除非用户主动清空关键词。

## 测试验收

- Repository 测试覆盖参数、分页和错误映射。
- UI 静态测试覆盖入口、加载/错误/回退文本、结果详情跳转和按钮类型。
- 验证云端搜索不会修改 `workbenchV2.candidates`。
- 验证搜索失败仍能看到本地候选人列表。
- 运行完整 `npm test`、生产构建和 `git diff --check`。

## 非目标

- 不在本阶段实现关键词高亮、语义搜索、Embedding 或 AI 精排。
- 不改变现有候选人云端读路径闸门。
- 不处理简历版本本地多出记录的迁移策略。
