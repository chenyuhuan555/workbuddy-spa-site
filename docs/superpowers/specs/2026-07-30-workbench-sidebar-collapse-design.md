# 工作台左侧导航栏收起设计

## 背景

新版工作台的左侧导航栏在桌面端固定占用 288px（较窄桌面为 244px）。用户希望在需要更大内容空间时主动收起导航栏，同时仍能通过图标快速切换模块并随时重新展开。

## 目标

- 桌面端允许用户在完整导航栏与 72px 窄图标栏之间切换。
- 收起后保留全部导航入口、当前菜单高亮和重新展开入口。
- 每次刷新页面都默认展开，不持久化上一次收起状态。
- 不改变现有业务数据、路由、云端同步、本地存储和权限行为。
- 保持现有窄屏响应式导航行为稳定。

## 非目标

- 不提供完全隐藏导航栏的模式。
- 不把收起状态写入 localStorage、IndexedDB 或云端工作区快照。
- 不重构现有导航配置、路由体系或工作台整体布局。
- 不调整右侧辅助栏的收起逻辑。

## 方案比较

### 方案 A：Vue 临时状态加样式类（采用）

在当前页面组件中增加一个只存在于本次页面生命周期的布尔状态，通过状态控制侧栏样式类、按钮文案和箭头方向。

优点：符合现有 Vue 写法；状态明确；易于测试；能正确支持键盘和无障碍属性；刷新后自然恢复默认展开。缺点：需要少量模板、状态和 CSS 修改。

### 方案 B：纯 CSS 复选框控制

用隐藏复选框和相邻选择器切换宽度。

优点：无需 Vue 状态。缺点：状态语义不清晰，无障碍属性难同步，模板结构耦合更强，不适合当前组件。

### 方案 C：完全隐藏导航栏

收起时把侧栏移出视口，只留下悬浮恢复按钮。

优点：可释放最多空间。缺点：导航入口不可见，重新展开入口不够稳定，也不符合用户选择的“保留窄图标栏”。

## 交互设计

### 展开状态

- 页面首次打开或刷新时始终处于展开状态。
- 保持现有桌面宽度规则：常规桌面 288px，宽度不超过 1380px 时为 244px。
- 显示品牌标题、导航图标、导航文字和侧栏底部原有内容。
- Logo 区域右侧增加一个收起按钮，图标指向左侧。
- 按钮的可访问名称和悬停提示均为“收起导航栏”。

### 收起状态

- 桌面端侧栏宽度固定为 72px。
- 隐藏品牌文字、导航文字和侧栏底部非必要文字，只保留必要图标或紧凑入口。
- 导航按钮图标水平居中，仍可正常点击。
- 当前导航项继续显示现有绿色高亮，确保用户知道所在模块。
- 切换按钮保持可见，图标指向右侧；可访问名称和悬停提示改为“展开导航栏”。
- 主内容区域通过现有 flex 布局自动占用释放出来的空间，不触发页面刷新或路由变化。
- 每个仅图标导航按钮保留现有 `aria-label`，并补充浏览器原生 `title` 提示。

### 窄屏行为

- 屏幕宽度不超过 820px 时继续使用现有 84px 自动图标栏。
- 窄屏下隐藏手动收起按钮，避免手动状态与响应式状态产生冲突。
- 从窄屏恢复到桌面宽度后，显示当前页面生命周期中的桌面手动状态；页面刷新仍默认展开。

### 动效

- 只对侧栏宽度和必要的可见性变化使用短时轻量过渡。
- 遵循 `prefers-reduced-motion: reduce`，用户要求减少动画时取消或显著缩短过渡。
- 不对主内容中的列表、卡片或业务数据添加额外动画。

## 实现边界

### 页面状态

增加 `workbenchSidebarCollapsed`，初始值为 `false`。该状态只在内存中存在，并从 Vue `setup` 返回给模板使用。

增加单一切换动作，将状态在 `true` 与 `false` 之间切换。切换动作不调用本地保存、云端同步或工作区快照保存。

### 模板

- 在 `.wb-v2-sidebar` 上根据状态添加收起样式类。
- 为导航栏设置稳定的 `id`，供切换按钮的 `aria-controls` 引用。
- 切换按钮必须声明 `type="button"`。
- 切换按钮使用动态 `aria-expanded`、`aria-label` 和 `title`。
- 导航项增加 `title`，确保收起后可识别；展开状态保留现有文字。
- 不改变 `workbenchNavItems` 数据内容和 `selectWorkbenchNav` 行为。

### 样式

- 收起样式必须比现有 288px、244px 桌面规则具有明确且可预测的优先级。
- 收起状态下压缩 Logo 区、导航区和底部区域的横向内边距。
- 隐藏文字时不能误隐藏 SVG、字符图标或无障碍名称。
- 保持侧栏的边框、背景、阴影、滚动和层级关系。
- 在 820px 以下由现有媒体查询接管布局，手动切换按钮不显示。

## 状态与数据流

1. 页面初始化，`workbenchSidebarCollapsed` 为 `false`。
2. 用户点击收起按钮，状态变为 `true`，模板添加收起样式类。
3. CSS 将侧栏变为 72px，并隐藏文字；主内容自动扩展。
4. 用户点击展开按钮，状态变回 `false`，恢复当前断点下的完整宽度。
5. 用户刷新页面，Vue 状态重新初始化为 `false`，导航栏默认展开。

此流程不产生异步请求，也不需要错误提示或重试机制。

## 无障碍要求

- 切换入口使用原生 `<button type="button">`，可通过 Tab 聚焦并用 Enter 或空格触发。
- `aria-expanded` 必须与实际展开状态相反映：展开为 `true`，收起为 `false`。
- `aria-controls` 指向导航栏的稳定 `id`。
- 图标作为装饰时设置 `aria-hidden="true"`，按钮名称由 `aria-label` 提供。
- 收起后所有导航项仍有可读的 `aria-label` 和可见的键盘焦点样式。
- 不能仅通过箭头方向或颜色表达状态。

## 验收标准

1. 桌面端首次打开新版工作台时，左侧导航栏完整展开。
2. 点击收起按钮后，侧栏变为约 72px，文字隐藏，全部导航图标和当前项高亮仍可用。
3. 点击展开按钮后，侧栏恢复当前桌面断点对应的完整宽度。
4. 收起状态下切换任一导航模块，功能、页面标题和选中高亮均正常。
5. 刷新页面后，无论刷新前是什么状态，导航栏都恢复展开。
6. 收起或展开不会触发本地保存、IndexedDB 写入或云端同步。
7. 屏幕宽度不超过 820px 时维持现有自动窄栏，手动开关不出现。
8. 切换按钮和导航项可通过键盘操作，辅助名称准确。
9. 现有页面测试、内联脚本解析检查和生产构建全部通过。

## 测试策略

- 增加静态契约测试，确认切换按钮具有 `type="button"`、`aria-expanded`、`aria-controls` 和动态名称。
- 增加状态契约测试，确认默认值为展开且不存在任何持久化读写。
- 增加样式契约测试，确认桌面收起宽度为 72px，窄屏规则仍为 84px且隐藏手动按钮。
- 运行项目完整自动化测试和生产构建。
- 在真实浏览器中分别验证常规桌面、1380px 以下桌面和 820px 以下窄屏：展开、收起、导航切换、刷新恢复和键盘操作。

## 回滚方式

该功能是独立的模板、内存状态和 CSS 增量。若发生布局回归，可撤销功能实现提交；由于没有数据迁移或持久化字段，回滚不需要处理用户数据。
